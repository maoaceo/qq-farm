# 本地多用户改造版

基线仓库：<https://github.com/liyangpengs/qq-farm-bot>

基线提交：`28a96145fb92c4b9e8e6e27222a0cc5b3735cf92`。

这是 maoaceo/qq-farm 多用户版本，已发布至本仓库，不是上游官方发布。网站是否更新以实际部署为准。

## 权限与功能

- 原管理员登录方式不变。侧栏新增「用户管理」。
- 管理员创建普通用户、禁用/启用用户、重置用户密码，但不能查看或管理其他用户的游戏账号。
- 普通用户使用自己的用户名、密码登录同一个地址，只能查看、添加、修改、删除、启停自己的游戏账号，以及设置自己的种植/自动化策略。
- 账号列表、CRUD 返回值、运行日志、账号日志和 Socket.IO 订阅均按账号归属过滤。
- 新账号的 `ownerId` 由服务器设置，不能由普通用户请求指定；旧账号缺少 `ownerId` 时默认为 `admin`。
- QQ/微信扫码任务绑定创建任务的用户，其他用户无法读取、取消或获取其授权 Code。
- 系统配置、登录服务地址及签名、全局下线提醒仅管理员可读写。普通用户仍可修改自己的登录密码。
- 禁用、重置密码、修改自身密码会撤销该用户会话并断开实时连接。不再提供跨用户账号转移接口。
- 禁用用户只关闭面板访问，不自动停止其已经运行的农场 Worker；管理员不能在自己的账号管理中看到或停止这些账号。
- 支持本地用户名/密码公开注册，登录页点击「没有账号？普通注册」，注册成功自动登录为普通用户（默认开启，`LOCAL_REGISTRATION_ENABLED=false` 可关闭）；可通过 Google / OIDC 首次认证自动注册，配置见 [OAuth/OIDC 文档](oauth-oidc.md)。仍不提供用户删除、计费、卡密、配额或每用户独立通知服务。

## 安全边界

这里是应用层逻辑隔离，不是每用户独立容器；管理员也只能查看和操作自己的游戏账号；服务器文件权限不属于此应用层隔离边界。
密码使用项目已有的加盐 PBKDF2 哈希。用户列表/API 不返回密码哈希。
认证会话在进程内保存，服务重启后需要重新登录。
管理员默认账号仍沿用上游初始化方式，首次使用必须立即修改默认密码。
不要把未加防护的管理端口直接暴露公网；使用 HTTPS、反向代理和网络访问控制。

修复了账号解析歧义：内部账号 ID 优先于可编辑 QQ/UIN 别名，防止别名劫持已检查的账号引用。删除所有账号后不再重置 nextId，避免后续账号复用已有日志 ID。

## 安装及迁移

### 建议：新目录试运行，保留原部署

1. 停止原实例，完整备份数据目录/卷，切勿只备份一个 JSON 文件。
2. 解压本包到一个全新的目录。包中包含源码、编译后的前端和后端，不包含依赖、凭据或实际账号数据。
3. 使用 Node.js 20.19+ 与 pnpm 10.30.2。在项目根目录执行：

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm build
```

4. 需要迁移时，把备份数据复制到新目录的 `core/data/`，不要覆盖备份。不要同时启动两个实例操作同一批游戏账号。
5. 从项目根目录启动（3008 仅作示例，需确保端口空闲）：

```bash
ADMIN_PORT=3008 pnpm -C core start
```

Windows PowerShell：

```powershell
$env:ADMIN_PORT='3008'
pnpm -C core start
```

6. 打开 `http://服务器地址:3008`，使用原管理员登录。进入「用户管理」创建用户，旧账号保留原 ownerId，缺少 ownerId 的旧账号归管理员；不提供转移其他用户账号的界面。
7. 用另一浏览器或无痕窗口登录普通用户，检查只显示其自己的游戏账号，再切换正式入口。

新安装没有原数据时，上游会初始化默认管理员 `admin` / `admin`，务必先修改密码再接入其他用户。
已有管理员密码不会被本改造重置。

### Docker

本包可按原来的 `docker compose up -d --build` 方式构建，但新目录中的 Compose 默认可能创建不同的命名卷。
迁移前确认实际挂载的卷；不能仅复制源码就假定旧数据已经迁移。请先备份，避免 `docker compose down -v`。

### 新增数据

普通用户及第三方绑定保存在 `core/data/users.sqlite`（Docker 内 `/app/core/data/users.sqlite`），旧 JSON 首次自动迁移并备份，详见 [SQLite 升级说明](sqlite-users.md)；账号归属保存在 `accounts.json` 的 `ownerId` 中。
请备份整个数据目录。

### 回滚

停止新版，恢复原代码与升级前的完整备份后启动。原版本不提供多用户隔离，不要把旧版入口继续开放给普通用户。

扫码测试中的远端 QQ/微信服务是桩，不会实际扫码或操作游戏；未使用真实游戏账号进行端到端测试。

请参阅包内 `VALIDATION.txt` 获取该包实际通过的测试统计。

## 普通注册安全与限流

无需 Google/妖火凭据或邮箱。用户名3–32位，密码至少6位且包含至少两类字符，要求确认密码。公开注册只创建普通用户，不接受客户端指定角色、归属或 ID。用户初始无游戏账号。后端按直连地址限制每15分钟10次注册尝试，反向代理可能使多人共享此限制；大型部署需可信边缘限流。可选启用 Turnstile，不包含邮件验证，公开站点应加访问控制和防滥用措施；需要时关闭注册。
